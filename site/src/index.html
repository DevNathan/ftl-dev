Features기능

Things I kept wishing for while writing ftl and couldn't find in any other extension.

ftl 짜면서 계속 아쉬웠는데 다른 익스텐션엔 없던 것들입니다.

Syntax highlighting하이라이팅

Directives, built-ins, ${…} inside strings, raw strings, square-bracket syntax and the HTML around them all get the right colors. No more squinting to see where a tag ends.

디렉티브, built-in, 문자열 안의 ${…}, raw 문자열, 대괄호 문법, 주변 HTML까지 제대로 칠합니다. 태그가 어디서 끝나는지 눈으로 더듬을 필요 없어요.

Go to definition & rename정의로 이동·이름 바꾸기

Ctrl+click a macro, function, variable or #import namespace and you're at the declaration. F2 renames, Ctrl+T searches the whole workspace.

매크로, 함수, 변수, #import 네임스페이스에서 Ctrl+클릭하면 선언으로 갑니다. 이름은 F2로 바꾸고, 워크스페이스 전체 검색은 Ctrl+T.

Completion & parameter hints자동완성·인자 힌트

Directives and built-ins up to FreeMarker 2.3.35, directive parameters, and parameter hints for your own #function / #macro.

FreeMarker 2.3.35까지의 디렉티브와 built-in, 디렉티브 인자, 직접 만든 #function / #macro의 인자 힌트가 뜹니다.

Diagnostics문법 검사

Unclosed tags, mismatched blocks, #switch mistakes, deprecated directives. If valid FTL gets a red line, that's a bug. Please tell me.

안 닫힌 태그, 짝 안 맞는 블록, #switch 실수, deprecated 디렉티브를 잡습니다. 멀쩡한 FTL에 빨간 줄이 뜨면 버그니까 알려 주세요.

ftldoc

Write Javadoc-style comments (@param, @return, @deprecated, @example, …) and they show up in hover, parameter hints and completion.

@param, @return, @deprecated, @example 같은 Javadoc식 주석을 달면 호버, 인자 힌트, 자동완성에 그대로 나옵니다.

Closing tags & indent태그 닫기·들여쓰기

Closing tags get filled in for you, indent follows FTL blocks, and renaming <#if> renames its </#if> too.

닫는 태그는 알아서 채워 주고, 들여쓰기는 FTL 블록 기준으로 맞춥니다. <#if> 이름을 고치면 </#if>도 같이 바뀝니다.

Outline & references아웃라인·참조 찾기

Document outline, find all references, separate colors for locals and parameters. Turn on strict mode if you want warnings for undeclared variables.

문서 아웃라인, 모든 참조 찾기, 지역 변수와 인자 구분 색. 선언 안 된 변수까지 경고받고 싶으면 strict 모드를 켜세요.

Vim / Neovim

A separate plugin, ftl-dev.vim, handles syntax, indent and closing tags. On Neovim you can also hook up the ftl-dev language server for hover, completion and diagnostics.

문법, 들여쓰기, 태그 닫기는 별도 플러그인 ftl-dev.vim이 맡습니다. Neovim이면 ftl-dev 언어 서버를 붙여서 호버, 자동완성, 진단도 쓸 수 있어요.

Diagnostics and hover진단과 호버

Some mistakes FreeMarker only reports when it renders the template. These show up while you type.

FreeMarker가 렌더링할 때가 돼서야 던지는 에러가 있습니다. 그런 걸 치는 동안 바로 보여 줍니다.

  • Mixing #on and #case in one #switch is a ParseException in FreeMarker 2.3.34. Here you get a red line before you even save.
  • #switch 하나에 #on과 #case를 섞으면 FreeMarker 2.3.34에선 ParseException입니다. 여기선 저장하기도 전에 빨간 줄이 뜹니다.
  • Hover a call to see its ftldoc, parameters and defaults.
  • 호출하는 곳에 마우스를 올리면 ftldoc, 인자, 기본값이 보입니다.

Install설치

Not much to it. Install it in your editor and open a .ftl, .ftlh or .ftlx file.

할 게 뭐 있겠습니까. 에디터에 설치하고 .ftl, .ftlh, .ftlx 파일을 열면 됩니다.

VS Code

Get it from the Visual Studio Marketplace, or paste this into Quick Open (Ctrl+P):

Visual Studio 마켓플레이스에서 받거나, Quick Open(Ctrl+P)에 이걸 붙여 넣으세요.

Cursor · CodeOSS

It's on Open VSX. Search FreeMarker (ftl-dev) in the Extensions view, or:

Open VSX에 있습니다. 확장 탭에서 FreeMarker (ftl-dev)를 검색하거나:

code-oss --install-extension nathan-0910.ftl-dev

Vim / Neovim

Use your plugin manager. With vim-plug:

플러그인 매니저로 설치하세요. vim-plug라면:
