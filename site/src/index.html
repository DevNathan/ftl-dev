Why ftl-dev existsftl-dev를 만든 이유

FreeMarker is used for more than rendering HTML. FTL code can include functions, macros, imports and branching logic. ftl-dev understands those parts, so you can jump to a definition, see problems as you type and check a function's docs at the call site.

FreeMarker는 HTML을 렌더링하는 데만 쓰이지 않습니다. FTL 코드에는 함수, 매크로, import와 분기 로직이 함께 들어갑니다. ftl-dev는 이런 코드를 이해해 정의로 이동하고, 입력 중 문제를 확인하고, 호출한 자리에서 함수 문서를 볼 수 있게 합니다.

Features기능

The extension covers the parts of FTL you work with every day.

자주 쓰는 FTL 편집 기능을 모았습니다.

Syntax highlighting하이라이팅

Directives, built-ins, ${…} inside strings, raw strings, square-bracket syntax and the HTML around them are all colored correctly.

디렉티브, built-in, 문자열 안의 ${…}, raw 문자열, 대괄호 문법, 주변 HTML까지 각각 알맞은 색으로 표시합니다.

Go to definition & rename정의로 이동·이름 바꾸기

Ctrl+click a macro, function, variable or #import namespace to go to its declaration. F2 renames, Ctrl+T searches the whole workspace.

매크로, 함수, 변수, #import 네임스페이스에서 Ctrl+클릭하면 선언으로 갑니다. 이름은 F2로 바꾸고, 워크스페이스 전체 검색은 Ctrl+T.

Completion & parameter hints자동완성·인자 힌트

Directives and built-ins up to FreeMarker 2.3.35, directive parameters, and parameter hints for your own #function / #macro.

FreeMarker 2.3.35까지의 디렉티브와 built-in, 디렉티브 인자, 직접 만든 #function / #macro의 인자 힌트가 뜹니다.

Diagnostics문법 검사

Unclosed tags, mismatched blocks, #switch mistakes, deprecated directives. A red line on valid FTL is a bug; please report it.

안 닫힌 태그, 짝 안 맞는 블록, #switch 실수, deprecated 디렉티브를 잡습니다. 올바른 FTL에 빨간 줄이 뜨면 버그이니 알려 주세요.

ftldoc

Write Javadoc-style comments (@param, @return, @deprecated, @example, …) and they show up in hover, parameter hints and completion.

@param, @return, @deprecated, @example 같은 Javadoc식 주석을 달면 호버, 인자 힌트, 자동완성에 그대로 나옵니다.

Closing tags & indent태그 닫기·들여쓰기

Closing tags are inserted automatically, indent follows FTL blocks, and renaming <#if> renames its </#if> too.

닫는 태그는 자동으로 넣고, 들여쓰기는 FTL 블록 기준으로 맞춥니다. <#if> 이름을 고치면 </#if>도 같이 바뀝니다.

Outline & references아웃라인·참조 찾기

Document outline, find all references, separate colors for locals and parameters. Turn on strict mode if you want warnings for undeclared variables.

문서 아웃라인, 모든 참조 찾기, 지역 변수와 인자 구분 색. 선언 안 된 변수까지 경고받고 싶으면 strict 모드를 켜세요.

Vim / Neovim

A separate plugin, ftl-dev.vim, handles syntax, indent and closing tags. On Neovim you can also hook up the ftl-dev language server for hover, completion and diagnostics.

문법, 들여쓰기, 태그 닫기는 별도 플러그인 ftl-dev.vim이 맡습니다. Neovim이면 ftl-dev 언어 서버를 붙여서 호버, 자동완성, 진단도 쓸 수 있어요.

Diagnostics and hover진단과 호버

Some template errors appear only when FreeMarker renders a file. ftl-dev can catch certain syntax and block errors as you edit.

템플릿 오류 중에는 FreeMarker가 파일을 렌더링해야 드러나는 것도 있습니다. ftl-dev는 일부 문법과 블록 오류를 편집 중에 표시합니다.

  • Mixing #on and #case in one #switch is a ParseException in FreeMarker 2.3.34. ftl-dev marks it as you type.
  • #switch 하나에 #on과 #case를 섞으면 FreeMarker 2.3.34에선 ParseException입니다. ftl-dev는 입력하는 동안 표시합니다.
  • Hover a call to see its ftldoc, parameters and defaults.
  • 호출하는 곳에 마우스를 올리면 ftldoc, 인자, 기본값이 보입니다.
