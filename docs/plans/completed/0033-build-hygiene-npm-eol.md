## Goal

1. **Package manager drift.** Make `vsix/extension` (and `vsix/server`) install and test cleanly with **npm** (`npm ci`), which is what CI uses (Node 20 + `npm ci` + `npm test`). Today the only failing unit test under `npm ci` is `commentMute.test.ts`, because it hard-codes pnpm store paths.
2. **Line endings.** Add `.gitattributes` to both repos so the repo is LF everywhere except Windows scripts. Then normalize the CRLF working trees so a non-Windows git shows no spurious changes and `vim/test/run.sh` runs under bash.

## Non-goals

- Committing, tagging, pushing, or version bumps (separate release step).
- Test-runner auto-discovery or other test-harness changes.
- CI workflow changes beyond what this plan strictly needs (none expected; CI already uses npm).
- A `"packageManager"` field, corepack, `only-allow`, or preinstall guards that need network at install time. These are optional and out of scope.
- Fixing vim `indent_align` test failures (separate item). The AC here is only that `run.sh` **starts**.
- Changing any grammar, provider, or Vim runtime behaviour.
- Using `git checkout` / `git reset` / `git stash` / `git add --renormalize` with index rewrites to fix EOL. Deletion is disallowed in this environment, and those commands delete and replace files and leave `.lock` files.
- Running `npm ci` / `npm install` or deleting `node_modules` in the user's folder. That is left to "User action" below.

## Approach

### Item 1

1. Edit `vsix/extension/package.json` in the user's folder to add the two devDependencies. Regenerate the lockfile **in the QA environment** (below): after the overlay, run `npm install --package-lock-only` in `extension/`. Then write the resulting `package-lock.json` back into `vsix/extension/` in the user's folder (stage it out of the container and commit it to the device path). Review the lock diff: there should be only root-dependency entries and no resolved-version changes. Do not run npm in the user's folder.
2. Edit `commentMute.test.ts` lines ~52-63 to plain package `require`s and `require.resolve` for `onig.wasm` (AC3). Keep the test logic otherwise identical.
3. Remove the untracked `extension/pnpm-lock.yaml`. If deletion is not permitted, request delete permission once. If that is declined, move it to `_to_delete/` outside the repo and tell the user. Add `pnpm-lock.yaml` and `yarn.lock` to `vsix/.gitignore`.
4. Check `vsix/server`: grep for `.pnpm`, check for a `pnpm-lock.yaml`, confirm its imports are covered by its own `package.json`. Record the result under "Results" below (AC6).

### Item 2

1. Write `.gitattributes` in each repo (AC9) with LF content.
2. Run a small Python script in each repo. It iterates `git ls-files -z`, skips binaries (attribute `-text`/`binary`, or a NUL byte in the content) and `*.ps1`/`*.cmd`/`*.bat`, replaces `b"\r\n"` with `b"\n"`, and writes back only if the content changed. For `*.ps1`, ensure CRLF in the working tree (the index stays LF, and git converts on checkout).
3. Verify with `git ls-files --eol`, `git status --short`, `git diff --stat`, and `git diff --ignore-cr-at-eol --stat` (the two diffs must match, AC12).
4. Note for Windows: with `.gitattributes` `eol=lf`, a Windows `core.autocrlf=true` no longer re-introduces CRLF for these files, because the attribute wins.

### User action (Windows, after merge)

```
cd vsix\extension
rmdir /s /q node_modules      (PowerShell: Remove-Item -Recurse -Force node_modules)
npm ci
npm test
```

Repeat `npm ci` in `vsix\server` if it was installed with pnpm. Do not run `pnpm install` in these packages any more. Agents do not run these steps in the user's folder. They are for the user only.

## QA environment

Commits are a non-goal, so a plain clone would test old code. Deletion is not allowed in the user's folder. Build and test checks therefore run in a defined clean environment **outside** the connected folder: the Cowork cloud container.

1. Clone both GitHub repos into the container: `https://github.com/DevNathan/ftl-dev` (vsix) and `https://github.com/DevNathan/ftl-dev.vim` (vim).
2. Bring in unpushed local commits. Stage the user's `vsix/.git/objects` and `vim/.git/objects` packs and loose objects, copy them into each clone's `.git/objects/`, and run `git checkout <local HEAD sha>` (read the sha with `git -C <repo> rev-parse HEAD` in the user's folder).
3. Overlay the changed working-tree files from the user's folder (the files listed by `git status --short` in each repo, staged from the device) onto the checked-out clones.
4. Run the build/test commands below there. For the lockfile (AC2), run `npm install --package-lock-only` there and write the result back into the user's folder.

EOL checks (AC9–AC12) run **in the user's folder** with read-only git commands only.
